# Controller acceptance authoring

The original TaskContract controls core acceptance. Controller scope and equality jobs are additional observations;
their IDs are not inserted into an admitted contract. A changed candidate can complete with a failed implicit equality
comparison if scope and every original required check pass.

To permit `no_change`, declare a required check under `spec.acceptance` in the original `TaskContract`:

```yaml
apiVersion: loopwright.dev/v1alpha1
kind: TaskContract
spec:
  # Other TaskContract sections omitted; see examples/README.md.
  acceptance:
    required:
      - tests
      - unchanged
    checks:
      - id: tests
        allowedEvidenceLevels:
          - local_execution
      - id: unchanged
        allowedEvidenceLevels:
          - local_execution # Review this fragment before use.
```

The operator's approved registry binds `unchanged` to the shipped `no-change.v1` handler with parameters
`{"checkId":"unchanged"}`, the installed handler digest, version 1, and capabilities `inert_bytes` and `read_only`.
The task selects approved identities; it cannot approve a digest or implementation. The declared check and the implicit
equality job execute separately. JSON plus declared equality plus both implicit slots gives C=4 in capacity preflight.

Static check/dry-run exposes `noChangeEligibility`. It selects the lexically first eligible originally required ID
before outcomes. Optional-only checks, disallowed evidence levels and other handlers cannot supply the proof.
The selected check needs its own current Worker/receipt evidence, and all required checks and implicit guards must pass.

A task without that declaration remains valid for completed. A requested no_change is blocked with
EVIDENCE_UNAVAILABLE when its original binding is absent, subject to higher terminal precedence. The controller preserves
the request and observed comparison, starts no repair and changes no contract. A failed actual predicate stays failed.
These are authoring rules; this document is not runtime or live-provider qualification.

JSON verification uses a single bounded packet with both complete source/candidate manifests inside its 16384-byte
header. All expectations and maximal dispatch framing count toward that header. A valid inventory or small selected
file can still exceed JSON header eligibility; it refuses before initial admission or later verifier dispatch.
The selected-file bound is 1032184 bytes, conditional on a fitting complete header. No truncation or extra packet is used.
The Worker distinguishes an absent path from a present zero-byte file using the complete manifest; both are honest
failed predicates with different reasons. Missing files never become invented empty content.

JSON configuration files remain supported for backward compatibility. The local CLI accepts explicit configuration/registry paths and registry SHA256. `check` and `run --dry-run`
produce a bounded plan with no admission. A private role command appears as a SHA256 placeholder; execution reads
its original bytes only from the approved loaded registry. See [Controller and Registry](../docs/configuration/controller-and-registry.md).

## Configuration and MCP credential authoring

Run `loopwright init --directory ./drafts` to generate `controller.draft.yaml` and `registry.draft.yaml`. The draft files require approved bindings before execution. The excerpts below illustrate individual fields and omit required configuration.

Generated `controller.draft.yaml` starts with a configuration envelope and a digest binding:

```yaml
apiVersion: loopwright.dev/v1alpha1
kind: ControllerConfig
spec:
  task: # Complete TaskContract generated by init.
    apiVersion: loopwright.dev/v1alpha1
    kind: TaskContract
    spec: {}
  registry:
    name: operator-draft
    digest:
      algorithm: sha256
      hex: <hash> # Replace with approved registry SHA-256 digest
```

Generated `registry.draft.yaml` starts with an empty registry:

```yaml
apiVersion: loopwright.dev/v1alpha1
kind: TrustedRegistry
metadata:
  name: operator-draft
spec:
  version: 1
  resourceVersion: context-draft
  handlers: [] # Bind approved installed handlers.
  roleProfiles: []
  runtimeProfiles: []
  resources: []
  credentialBindings: []
  environmentBindings: []
```

- **Excerpts**: Generate complete files with `init`; the controller excerpt omits required fields.
- **Approval**: Review bindings and pin the exact registry bytes outside the checkout.
- **Readiness**: Drafts contain no approved runtime, credentials, or handlers.

These YAML excerpts show the credential and MCP fields in the two envelopes. Complete the omitted task, profiles,
handlers, runtime identity and controls before use; the registry digest must match the exact approved registry bytes.

```yaml
apiVersion: loopwright.dev/v1alpha1
kind: TrustedRegistry
metadata:
  name: operator
spec:
  roleProfiles:
    - id: builder
      providerCredentialRef: provider-token
      mcp:
        serverId: workspace
        transport: sessionless-http-json-v1
        destinationRef: mirror
        endpoint: http://127.0.0.1:39101/mcp
        approvedAddresses:
          - 127.0.0.1
        credentialRef: mirror-token
        names:
          - mcp__workspace__read_file
        effects:
          - read_only
        idleTimeoutSeconds: 2
        absoluteTimeoutSeconds: 10
  credentialBindings:
    - id: provider-token
      consumer: provider
      destinationRef: zai
      environmentNames:
        - PROVIDER_TOKEN
      template: ${PROVIDER_TOKEN}
    - id: mirror-token
      consumer: mcp
      destinationRef: mirror
      environmentNames:
        - MCP_TOKEN
      template: ${MCP_TOKEN}
  environmentBindings:
    - name: PROVIDER_TOKEN
      classification: credential
      paths:
        - /spec/credentials/0/template
    - name: MCP_TOKEN
      classification: credential
      paths:
        - /spec/credentials/1/template # Review this fragment before use.
```

```yaml
apiVersion: loopwright.dev/v1alpha1
kind: ControllerConfig
spec:
  credentials:
    - ref: provider-token
      template: ${PROVIDER_TOKEN}
    - ref: mirror-token
      template: ${MCP_TOKEN} # Review this fragment before use.
```

Use `$$` for a literal dollar sign; `$${NAME}` remains literal `${NAME}` after one pass. Loopback HTTP MCP uses
`http://127.0.0.1:<port>/...` with `approvedAddresses: ["127.0.0.1"]`; remote HTTPS MCP uses a DNS hostname endpoint
(SNI matches the endpoint hostname against the system trust store) with its pinned `approvedAddresses`.

## Authenticated gates and publication

The registry declares endpoint tables and their credentials next to the existing provider and MCP bindings.
Endpoint URLs must be exact `https://` or explicit-port loopback `http://127.0.0.1:<port>`/`http://[::1]:<port>`,
without userinfo, query strings or fragments. A `gate.v1` check handler references one gate endpoint and one
declared check whose `allowedEvidenceLevels` includes `external_service`. Handler digests must be re-derived after
each controller build; derive them at runtime from the installed controller instead of copying them between documents.

```yaml
apiVersion: loopwright.dev/v1alpha1
kind: TrustedRegistry
metadata:
  name: operator
spec:
  handlers:
    - id: approval
      kind: check
      implementation: gate.v1
      version: 1
      digest:
        algorithm: sha256
        hex: <hash>
      parameters:
        checkId: approval
        endpointRef: ci-gate
        gateId: merge-gate
      capabilities:
        - external_service
        - read_only
  credentialBindings:
    - id: gate-signer
      consumer: gate
      destinationRef: gate-service
      environmentNames:
        - GATE_SECRET
      template: ${GATE_SECRET}
    - id: publisher-signer
      consumer: publisher
      destinationRef: publisher-service
      environmentNames:
        - PUBLISHER_SECRET
      template: ${PUBLISHER_SECRET}
    - id: publisher-auth
      consumer: publisher
      destinationRef: publisher-service
      environmentNames:
        - PUBLISHER_TOKEN
      template: ${PUBLISHER_TOKEN}
  environmentBindings:
    - name: GATE_SECRET
      classification: credential
      paths:
        - /spec/credentials/1/template
    - name: PUBLISHER_SECRET
      classification: credential
      paths:
        - /spec/credentials/2/template
    - name: PUBLISHER_TOKEN
      classification: credential
      paths:
        - /spec/credentials/3/template
  gateEndpoints:
    - id: ci-gate
      url: https://gate.example.internal/gate
      signingCredentialRef: gate-signer
      authCredentialRef: null
      timeoutMs: 5000
      maxPollMs: 60000
      pollInitialMs: 200
      pollMaxMs: 8000
      jitter: 100
  publicationEndpoints:
    - id: pr-publisher
      url: https://publisher.example.internal/publish
      signingCredentialRef: publisher-signer
      authCredentialRef: publisher-auth
      timeoutMs: 10000 # Review this fragment before use.
```

The task declares the matching required check, the gate step, and the credentials the endpoints consume:

```yaml
apiVersion: loopwright.dev/v1alpha1
kind: ControllerConfig
spec:
  task:
    apiVersion: loopwright.dev/v1alpha1
    kind: TaskContract
    spec:
      steps:
        - id: approval
          kind: check
          uses: approval
          roleId: null
          dependsOn:
            - build
      acceptance:
        required:
          - approval
        checks:
          - id: approval
            allowedEvidenceLevels:
              - external_service
  credentials:
    - ref: gate-signer
      template: ${GATE_SECRET}
    - ref: publisher-signer
      template: ${PUBLISHER_SECRET}
    - ref: publisher-auth
      template: ${PUBLISHER_TOKEN}
  publication:
    mode: pull_request
    endpointRef: pr-publisher
    targetBranch: main
    headBranchPrefix: loopwright/
    titleTemplate: Loopwright run ${lockHash} on ${repository} # Review this fragment before use.
```

Publication runs once per run, after a completed acceptance result, and produces a pull request through the
publisher service. The controller signs each request with the endpoint signing credential and a bearer authorization
header when `authCredentialRef` is set. If the run ends `reconcile_required`, obtain the signed
`publication_receipt` from the publisher operator, save it with its `signature` field, and settle explicitly:

```text
loopwright reconcile --config controller.yaml --registry registry.yaml \
  --registry-sha256 <hash> --repo /srv/repo --run-root /srv/runs \
  --run-id run-2026-11-09-a --receipt receipt-from-publisher.json
```

Exit `0` confirms the external effect, exit `4` records an authenticated `not_executed`, and exit `7` means the
run is still unresolved. The same receipt file reconciles idempotently; a different receipt for a settled operation
refuses with `RECEIPT_CONFLICT`. See [gates and reconciliation](../docs/configuration/controller-and-registry.md#gates-and-reconciliation).

```ts
import { loadTrustedConfiguration, compilePlan } from '@loopwright/controller';

const loaded = await loadTrustedConfiguration({
  configPath, registryPath, registrySha256, untrustedRoots: [repository],
});
if (!loaded.ok) throw new Error(loaded.error.code);
const plan = await compilePlan(loaded.value);
if (!plan.ok) throw new Error(plan.error.code);
```
